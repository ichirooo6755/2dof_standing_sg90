# 転倒後の静止待ちを含む起き上がり学習

元の95.1gのSG90モデル、ファームウェアのIMUフィルタと再試行処理、既存PPOの重みを使用する。転倒の初期姿勢・速度・腕角度を変え、サーボの目標を保持して機体を解放する。静止待ちが完了してから、既存と同じ20ms周期で方策を実行する。

## 静止判定の比較

前後・左右・斜めの8方向それぞれで、85°・135°・反転の3条件を同じシードで比較した。角度は開始時の台座の傾き。135°と反転はアームを曲げた姿勢から開始する。ここでの待機判定はシミュレーション用候補で、実機の稼働ログではない。

| MuJoCoの計算刻み | IMUの静止判定 | 静止0.3秒で指令開始 | 静止0.5秒で指令開始 |
|---|---|---:|---:|
| 1ms | IMUの各サンプル | 13/24 | 13/24 |
| 1ms | IMU平滑化と姿勢変化確認 | 17/24 | 14/24 |
| 0.5ms | IMUの各サンプル | 12/24 | 12/24 |
| 0.5ms | IMU平滑化と姿勢変化確認 | 19/24 | 19/24 |

開始できた全試行で既存方策が起き上がった。開始しなかった試行では、シミュレーションの待機上限5秒までに静止条件がそろわなかった。失敗例では接触が変わるたびに加速度と角速度が変動し、待機時間がリセットされた。平滑化版は0.08秒の時定数で加速度・角速度を平均し、静止候補の区間に重力方向が3°以上ずれた場合にも計時をやり直す。0.3秒版の指令開始は静止と判定し始めてから最短約0.303秒だった。実機の転倒に対する効果は未確認。

[1msのサンプル判定](../results/gated_baseline_raw/held_out_initial.json) · [1msの平滑化判定](../results/gated_baseline_imu_smoothed/held_out_initial.json) · [0.5msのサンプル判定](../results/gated_baseline_05ms_raw/held_out_initial.json) · [0.5msの平滑化判定](../results/gated_baseline_05ms_smoothed/held_out_initial.json)

別の24条件では計算刻み1ms、待機上限10秒で再評価した。0.3秒待ちの指令開始は19/24から23/24、起き上がりは19/24から22/24になった。平滑化版で失敗した2件は反転からの試行で、1件は静止判定を通らず、1件は方策の実行中に制御異常で停止した。0.5秒では指令開始と起き上がりがともに16/24から22/24になった。どちらの待ち時間でも、静止条件を満たす前の指令変更は0件だった。[別条件のサンプル判定](../results/gated_fresh_raw/held_out_initial.json) · [別条件の平滑化判定](../results/gated_fresh_smoothed/held_out_initial.json)

## 計算ノードでの実行

プロジェクトのルートから計算用ファイルをまとめる。

```sh
python3.12 sim/sg90_1000mah/gated/pack.py gated_training.tar.gz
```

計算ノード側でアーカイブを新規作業ディレクトリへ展開する。Python 3.12とC++コンパイラを使い、同じディレクトリで実行する。

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -r sim/sg90_1000mah/requirements-lock.txt
.venv/bin/python -u sim/sg90_1000mah/gated/train_gated.py \
  --steps 1048576 --envs 8 --out results/gated_recovery
```

追加学習は静止0.3秒の設定。検証では0.3秒と0.5秒の両方を同じ条件で走らせる。131,072ステップごとにモデルを保存し、学習と別のシードで成功数と復帰時間を比較して選ぶ。各試行の転倒検知時刻、静止開始、方策の開始、サーボ指令が変わった時刻をJSONに記録する。実機への指令と書き込みは行わない。
